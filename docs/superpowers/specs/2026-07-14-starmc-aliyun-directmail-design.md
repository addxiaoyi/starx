# StarMC Alibaba Cloud DirectMail Design

## Goal

Replace the Ethereal test SMTP transport with Alibaba Cloud DirectMail so StarMC verification codes reach real mailboxes. Keep the existing SuperTokens Passwordless flow and the root-domain Feishu mailbox service unchanged.

## Scope

- Configure DirectMail for transactional authentication mail.
- Use `notify.star-mc.top` as an isolated sender domain.
- Use `noreply@notify.star-mc.top` as the application sender.
- Add a production guard that rejects sandbox SMTP providers.
- Deploy with rollback and verify a complete email-code session.

This change does not replace Feishu MX records for `star-mc.top`, add marketing mail, or change the Passwordless API contract.

## Architecture

```text
Browser
  -> POST /auth/signinup/code
  -> SuperTokens Passwordless
  -> Nodemailer SMTP transport
  -> smtpdm.aliyun.com:465 (TLS)
  -> recipient mailbox

Browser
  -> POST /auth/signinup/code/consume
  -> SuperTokens session cookie
  -> /api/auth/status
  -> /api/user/me
```

DirectMail owns only `notify.star-mc.top`. Feishu continues to own the root-domain inbound mail configuration. DNS records for the sender subdomain must match the values generated by the DirectMail console; they must not be copied from examples because Alibaba Cloud can vary verification targets by account and region.

## DirectMail Configuration

1. Activate Alibaba Cloud DirectMail in the same Alibaba Cloud account that manages the domain.
2. Add `notify.star-mc.top` as the sender domain.
3. Add the exact MX, SPF/TXT, DKIM/CNAME, and ownership records shown by the DirectMail console.
4. Wait until DirectMail reports the sender domain as verified.
5. Create `noreply@notify.star-mc.top` as the sender address.
6. Enable SMTP sending and set a dedicated SMTP password.
7. Store the SMTP password only in the deployment environment. Do not place it in documentation, source control, browser storage, logs, or chat.

The backend runtime values are:

```env
STARMC_SMTP_HOST=smtpdm.aliyun.com
STARMC_SMTP_PORT=465
STARMC_SMTP_SECURE=true
STARMC_SMTP_USER=noreply@notify.star-mc.top
STARMC_SMTP_FROM_EMAIL=noreply@notify.star-mc.top
STARMC_SMTP_FROM_NAME=StarMC
```

`STARMC_SMTP_PASSWORD` is supplied separately as a deployment secret. `tools/starmc-simple-config.local.env` is the local secret overlay. The generated backend file remains `重构/backend/.env.generated`. Production secrets are transferred through the server environment or a protected server-side env file and must never be printed during deployment.

## Application Changes

`重构/backend/src/auth/supertokensEmailDelivery.js` will classify known sandbox SMTP hosts. Production configuration must fail fast when the host is `smtp.ethereal.email` or another explicitly listed test-only provider. Development may continue using Ethereal for preview testing.

The production readiness response must not report SMTP as configured when a sandbox transport is selected. Existing input validation, bilingual content, rate limits, Passwordless challenge creation, and session creation remain unchanged.

The configuration doctor will surface a plain error that identifies the invalid provider without printing usernames or passwords. No credential value may appear in structured logs or API responses.

## Error Handling

- Missing or sandbox production SMTP configuration prevents a release from passing readiness checks.
- SMTP authentication or TLS failure blocks cutover and leaves the current production release active.
- DirectMail domain verification failure blocks sender-address creation and deployment.
- Send failures return the existing safe authentication error; detailed SMTP errors remain server-side and must be scrubbed of credentials.
- DNS changes are limited to `notify.star-mc.top`, so rollback does not affect Feishu mail on `star-mc.top`.

## Testing

Unit coverage will verify:

- DirectMail settings map to host `smtpdm.aliyun.com`, port `465`, and TLS enabled.
- production rejects `smtp.ethereal.email`;
- development may use Ethereal;
- readiness is false for a production sandbox transport;
- errors do not include SMTP passwords.

Deployment verification will run:

1. backend lint and complete tests;
2. frontend tests, TypeScript, and production build;
3. `nodemailer.verify()` against DirectMail without logging credentials;
4. a real code request to a mailbox controlled by the operator;
5. code consumption followed by authenticated `/api/auth/status` and successful `/api/user/me`;
6. sign-out and a second email-code sign-in;
7. console inspection for unexpected authentication errors.

## Deployment And Rollback

Before changing production, create timestamped backend and environment backups. Update the protected SMTP configuration, regenerate or install the backend env, and restart `starmc-api` with updated environment variables.

Cutover succeeds only after SMTP verification and the real mailbox flow pass. On failure, restore the previous backend environment and process configuration, restart PM2, and retain diagnostic logs with secrets removed. The previous Ethereal configuration may be restored only for local diagnostics; it must not be reported as production-ready.

## Security

- Rotate the previously exposed SSH password before deployment and prefer SSH key authentication.
- Use a dedicated DirectMail SMTP password with the smallest available scope.
- Never reuse the Alibaba Cloud account password.
- Apply DirectMail rate and daily-send limits in addition to the existing API limiter.
- Monitor bounce rate and provider complaints; disable sending if credentials are abused.
- Keep authentication responses account-enumeration resistant and never expose delivery internals to the browser.

## Acceptance Criteria

- `notify.star-mc.top` is verified by DirectMail without changing root-domain Feishu MX records.
- production uses `smtpdm.aliyun.com:465` with TLS.
- production cannot start or report healthy with Ethereal.
- a new user receives a six-digit code in a real mailbox.
- consuming the code creates a SuperTokens cookie session.
- `/api/auth/status` reports `authenticated: true` and `/api/user/me` returns the synchronized user.
- no SMTP password, SSH password, verification code, or session token is present in logs or built frontend assets.
