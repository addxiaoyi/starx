# StarX 0.4.1

0.4.1 增加代理端外部握手认证，公共扩展 API 仍为 1.0.0。

## 外部握手认证

Velocity 插件数据目录中会生成 `external-handshake.key`。文件不存在时生成新的 32 字节随机密钥，后续启动复用现有密钥。默认安装可在代理端执行：

```powershell
Get-Content .\plugins\starx\external-handshake.key
```

外部客户端必须把密钥放进初始 Minecraft Handshake 数据包的 `Server Address` 字段，原始值严格使用三个字段：

```text
<服务器地址>\0starx-handshake\0<密钥>
```

例如，客户端实际发送的字符串由 `服务器地址 + NUL + starx-handshake + NUL + 文件中的密钥` 组成。客户端框架必须允许保留并发送原始 NUL 字符；用户名、聊天消息、插件消息、查询参数或普通 TCP 连接都不会触发检测。

认证检测发生在 Velocity 的早期 `LoginEvent` 阶段，读取 `Player.getRawVirtualHost()`。地址字段非空且标记、密钥完全匹配后，连接会保留该接入信号，但仍进入正常的身份和密码认证流程：握手密钥不能单独证明 Minecraft 玩家身份。错误或缺失密钥同样按普通密码认证处理。

## 安全操作

- 只把密钥提供给需要连接该代理的受信外部服务，不要提交到代码仓库或写入公共日志。
- 轮换密钥时先停止代理，将旧的 `external-handshake.key` 移到安全备份位置，再启动代理生成新密钥，并同步更新外部客户端。
- 一个代理数据目录对应一个握手密钥。通过其他代理或会改写 `Server Address` 的中间层连接时，原始字段可能无法到达 Velocity，因此不会被识别。

## 升级

将 Velocity 和所有 Paper/Folia 实例替换为同一份 `starx-universal-0.4.1.jar`，完整重启后确认 Velocity 健康接口、后端 heartbeat、网站节点状态和 `StarX backend ready`。

同一实例不要同时放置 `starx-universal.jar` 与旧的 `starx-velocity.jar` 或 `starx-server.jar`。
