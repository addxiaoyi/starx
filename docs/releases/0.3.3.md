# StarX 0.3.3

0.3.3 聚焦 AuthX/UniAuth 账号迁移和玩家资料同步。公共扩展 API 仍为 1.0.0，没有破坏性 API 变更。

## 主要变化

- UniAuth 登录成功后可同步邮箱和外部用户 ID。
- 资料同步默认只填补空值，不覆盖已有本地资料，并保留邮箱唯一性约束。
- 待迁移账号可继续通过 UniAuth 验证；成功后保存 BCrypt 本地密码并标记迁移完成。
- UniAuth 客户端兼容多种嵌套资料字段，并支持公钥轮换后的安全重试。
- 响应校验头不完整或校验不通过时直接失败，不降级为未校验响应。
- 新增资料解析、配置、迁移和 Velocity 认证接线测试。

## 兼容范围

- Java 21
- Velocity `3.5.0-SNAPSHOT` build 606
- Paper/Folia 1.21.0–1.21.11
- Extension API 1.0.0

## 升级步骤

1. 备份 Velocity 的 StarX 数据库、配置和现有 JAR。
2. 在 Velocity 与所有 Paper/Folia 实例中替换为同一个 `starx-universal-0.3.3.jar`。
3. 删除其他旧版 StarX JAR，避免重复插件 ID。
4. 配置 `uniauth.profile-sync`，默认保持 `overwrite-local-values: false`。
5. 使用外部账号迁移时启用 `uniauth.bridge-mode`，并先执行账号清单试运行。
6. 完整重启 Velocity 和后端实例，检查 `/starx doctor` 与 `/starxserver doctor`。
7. 核对迁移前后账号总数、待迁移数、已迁移数和数据库完整性。

## 验证

- 完整插件 `clean test` 通过。
- 发布元数据、Public API、扩展示例和 Universal JAR 校验通过。
- Universal JAR 使用可复现归档设置生成，并随 Release 提供 SHA-256 与发布清单。

生产账号迁移必须保留可回滚数据库副本。UniAuth 不可达时，尚未完成本地密码迁移的账号无法完成远端认证。
