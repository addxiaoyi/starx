# StarX 0.4.2

0.4.2 汇总认证稳定性修复、配置目录整理、中文配置教程和外部握手认证能力，公共扩展 API 仍为 1.0.0。

## 配置目录和投影文件

运行时配置现在位于 `plugins/starx/config/`：

- `core.yml`：自动配置、管理 HTTP、兼容性和数据库。
- `auth.yml`：认证、UniAuth、TOTP 和玩家提示文字。
- `network.yml`：网站同步、网络自动化、FRP、证书和 NapCat。
- `modules.yml`：模块开关和玩家列表。
- `uworld.yml`：认证世界、诊断世界和投影加载。

投影文件放到 `plugins/starx/assets/uworld/`，然后在 `config/uworld.yml` 中使用相对于 `plugins/starx/` 的路径，例如：

```yaml
uworld:
  auth:
    world:
      loader-type: AUTO
      file-name: assets/uworld/auth_world.schem
```

已有分片不会被默认模板覆盖；升级旧实例前请备份 `plugins/starx/`，修改后完整重启 Velocity。

## 认证和握手

正版、离线和外部可信身份会沿用各自的身份来源进入认证流程，普通离线账号仍按密码认证处理。代理数据目录会生成 `external-handshake.key`，外部连接端必须在初始 Minecraft Handshake 的 `Server Address` 字段发送：

```text
<服务器地址>\0starx-handshake\0<密钥>
```

这里的 `\0` 代表真实 NUL 字节，不是可见字符、URL 编码或聊天消息。错误或缺失密钥会按普通密码认证处理。

## 升级

将 Velocity 和所有 Paper/Folia 实例替换为同一份 `starx-universal-0.4.2.jar`，完整重启后确认 Velocity 健康接口、后端 heartbeat、网站节点状态和 `StarX backend ready`。

同一实例不要同时放置 `starx-universal.jar` 与旧的 `starx-velocity.jar` 或 `starx-server.jar`。
