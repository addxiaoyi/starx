# StarX 0.3.5

0.3.5 是认证与插件消息信任边界的安全修订版本，兼容范围与 0.3.4 相同，公共扩展 API 仍为 1.0.0。

## 功能修复

- 认证 Uworld 强制发送并保持 Adventure 模式；虚空救援阈值可配置，传送确认前抑制重复救援，失败或确认后允许后续救援。
- Proxy Ping 使用 Velocity 实际在线人数，最大人数不会小于在线人数，并保留原有版本、样本玩家、图标和模组字段。
- 启动配置加载前安全迁移 MiniMOTD：支持 `motds` 数组及旧 `line1/line2`，一次性标记，保留自定义 StarX 值，并拒绝符号链接、越界文本、无效/超大文件和覆盖现有图标。

## 安全修复

- `starx:main` 只处理由后端服务器连接发送的消息，玩家客户端无法再注入 Plan 统计或玩家状态事件。
- `starx:anticheat` 只处理由后端服务器连接发送的检测结果，玩家客户端无法再伪造其他玩家的违规记录。
- 两个私有频道均在 Velocity 上显式标记为已处理，防止消息继续转发。
- BCrypt 对 UTF-8 长密码采用 SHA-512 预处理策略，避免达到原生 72 字节边界时注册或 UniAuth 迁移异常。
- 现有短密码哈希保持原格式和验证兼容；损坏或缺失哈希按认证失败处理。

## 兼容范围

- Java 21、25
- Velocity `3.5.0-SNAPSHOT` build 606
- Paper/Folia 1.21.0–1.21.11
- Paper/Folia 26.1.x–26.2.x
- 更高的 26.x 继续以 `DEGRADED` 非阻断方式运行
- Extension API 1.0.0

## 验证

- 插件消息来源信任回归测试通过。
- ASCII、Unicode 长密码和损坏哈希回归测试通过。
- 完整插件测试、Public API、扩展示例、Paper 26.1/26.2 API 编译和 Universal JAR 校验通过后发布。

## 配置

- `uworld.auth.world.void-rescue-threshold` 默认 `16`，表示低于出生点多少格触发虚空救援。
- `modules.starx.motd.maximum-players` 默认 `100`；运行人数超过该值时 Ping 最大人数自动抬高。
- MiniMOTD 迁移只在 StarX 数据目录中执行一次，迁移结果写回 `config.yml`，自定义现值不会被覆盖。

## 升级

将 Velocity 和所有 Paper/Folia 实例替换为同一份 `starx-universal-0.3.5.jar`，完整重启后确认 Velocity 健康接口、后端 heartbeat 和 `StarX backend ready`。
