# StarX 0.3.2

0.3.2 聚焦生产可靠性、认证挑战持久化和安全受限的网络自动化。公共扩展 API 仍为 1.0.0，没有破坏性 API 变更。

## 主要变化

- 新增多来源公网地址判断、FRP 检测/托管事务、运行时端口租约、HTTP-01 前置检查和证书续期策略。
- HTTP API 仍默认仅监听 `127.0.0.1`；FRP 默认是 `detect`，`auto-apply` 为 `false`；证书自动执行默认关闭。
- 绑定、邮件验证和跨设备审批挑战支持数据库持久化、重启恢复和并发执行租约。
- 后端命令邮箱与节点注册表加强过期清理、并发一致性和故障恢复。
- 队列与智能队列加强连接超时、故障切换、状态恢复和压力场景处理。
- Paper/Folia 自动配置加强 heartbeat 发现、节点身份推断和不同启动顺序下的恢复。
- 皮肤桥、NapCat、网站同步、API 暴露判断和兼容性报告增加更严格的错误处理。
- 修复 Paper/Folia 有效命令别名被 Velocity 文档测试误判的问题。

## 兼容范围

- Java 21
- Velocity `3.5.0-SNAPSHOT` build 606
- Paper/Folia 1.21.0–1.21.11
- Extension API 1.0.0

其他平台版本会根据运行时规则标记为 `UNKNOWN`、`DEGRADED` 或 `UNSUPPORTED`，不会自动宣称已认证。

## 升级步骤

1. 备份现有 JAR、配置和数据目录。
2. 在 Velocity 与所有 Paper/Folia 实例中替换为同一个 `starx-universal-0.3.2.jar`。
3. 删除旧版 StarX 分端或 Universal JAR，避免重复插件 ID。
4. 先启动 Velocity，再启动后端；首次启动会将 Velocity 配置升级到 schema 5。
5. 执行 `/starx doctor`、`/sxnodes status` 和 `/starxserver doctor`。
6. 检查 `network-automation.json`、`runtime-endpoint.json`、兼容性报告和 heartbeat 状态。
7. 只有在确认 FRP 主配置、域名、80 端口路由和回滚方案后，才启用托管 FRP 或证书自动执行。
8. 完整重启一次，确认配置迁移、挑战恢复和节点同步。

## 验证

- 完整插件 `clean test` 通过。
- Public API JAR、扩展示例和 Universal JAR 校验通过。
- Universal JAR 使用可复现归档设置生成，并随 Release 提供 SHA-256 与发布清单。

自动化结果不等于生产实服验收。真实多 JVM、真实客户端、第三方插件组合、FRP 公网链路、证书签发、故障恢复和回滚仍需在部署环境完成。
