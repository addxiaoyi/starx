# StarX 0.5.1

`starx-universal-0.5.1.jar`

## 稳定版变更

- 后端心跳命令解码补齐 `proxy.skin.update` 支持：此前 mailbox 中积压的皮肤推送会被判定为不支持命令，导致心跳交换失败并退回 player-carried bridge；现在无玩家在线的子服也能通过心跳通道及时接收皮肤更新。
- 心跳响应携带 mailbox 积压数量（`httpCommandsQueued`），后端在仍有积压时立即发起下一轮交换，实现"满缓冲区即拉取"，离线皮肤同步延迟从分钟级降至秒级。
- 纹理同步在受限网络环境下默认禁用 Mojang API 回退（`SkinsRestorerSkinRepository.setAllowMojangApi(false)`），仅读取 SkinsRestorer 本地缓存，消除 SSL 握手超时导致的线程堆积与 CPU 飙升。
- 纹理缓存改为 LRU+TTL 淘汰策略（2048 条 / 1 小时），替代"满则清空"策略，避免缓存抖动引发的重复下载风暴。

## 新增

- 网站同步 HTTP 客户端接入熔断器与信号量限流；连续失败达到阈值后快速拒绝请求。新增配置：

  ```yaml
  website-sync:
    circuit-breaker:
      enabled: true
      failure-threshold: 10
      open-timeout-seconds: 60
  ```

- 新增运行时指标收集：心跳/清单/纹理上传成败计数、缓存命中率、熔断与限流拒绝计数、最近延迟，通过 `VelocityWebsiteSync.metrics()` 与 `circuitState()` 暴露。
- 新增插件自动更新检查器（默认关闭）：支持 GitHub Releases 与 Maven Central 更新源；下载过程受熔断、信号量限流、超时与 64 MiB 大小上限保护，文件原子写入 `plugins/starx/updates/`，重启后生效。新增 `config/update.yml` 配置分片。

## 验证

- 全部模块编译通过；Velocity 运行时 JAR 校验通过。
- 心跳交换、皮肤桥接与网站同步相关测试门禁保持绿色。
- `AUTOMATED_VERIFIED` 仅表示自动化门禁；生产部署、真实服务器和客户端验收仍需单独执行。

## 部署

将同一份 `starx-universal-0.5.1.jar` 放入 Velocity、Paper/Folia 各自的 `plugins/` 目录，保留旧 JAR 备份后完整重启对应 JVM。不要使用 `/reload` 或同时保留旧的分端 JAR。

升级前若曾遇到 CPU 异常占用，建议同时确认 `website-sync.textures.enabled` 保持按需开启，并在受限网络环境下保持 Mojang API 回退为默认关闭状态。
