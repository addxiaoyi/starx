# StarMC 正式上线门禁

只有所有 P0 项目完成后才能开放公网。代码测试通过不等于实际基础设施已经完成。

## P0：必须完成

- [ ] `npm run production:verify` 成功。
- [ ] 生产 Velocity 设置为 `online-mode=true`；不存在未经书面批准的公网离线模式例外。
- [ ] Paper 只绑定回环地址，并启用 modern forwarding。
- [ ] HTTP API 和 RCON 只绑定回环地址。
- [ ] 防火墙只开放需要的玩家端口：Java TCP；启用 Bedrock 时开放对应 UDP。
- [ ] 使用专用低权限服务身份，不使用日常登录管理员账号运行游戏进程。
- [ ] 已人工审阅并接受 Mojang EULA。
- [ ] `production.config.json` 中 Java 路径、端口、节点名、MOTD、最大人数与实际环境一致。
- [ ] JVM 堆大小基于目标硬件和压力测试确定，不直接照搬示例 4 GiB。
- [ ] 完整发布清单包含 Velocity、Paper、StarX、Geyser/Floodgate 及其非敏感版本配置。
- [ ] 发布 JAR 的来源、版本、许可证和 SHA-256 已记录。
- [ ] `backup.mirrorRoot` 指向与运行磁盘不同的故障域；NAS/对象存储同步凭据已验证。
- [ ] 已从镜像备份在另一目录或另一主机完成真实恢复演练，并记录 RTO/RPO。
- [ ] 已安装 watchdog 和每日冷备份计划任务，并确认使用预期身份运行。
- [ ] 外部监控已采集 `/v1/health`、`state/alert.json` 和 `production-events.jsonl`。
- [ ] 已验证 watchdog 熔断告警能送达值班人员，而不是只写本地文件。
- [ ] 已设置 DNS、DDoS 防护、上游防火墙和连接速率限制。
- [ ] 管理员 Minecraft 账号启用最小权限、独立身份和二次认证方案。
- [ ] 若启用第三方离线认证、Uworld、数据库或消息系统，已单独完成安全审计和故障演练。

## P1：开放前验证

- [ ] 50、100、目标峰值人数的分阶段压力测试完成。
- [ ] 峰值 TPS、MSPT、GC 停顿、堆占用、网络和磁盘延迟已记录。
- [ ] 完成同时登录、快速移动加载区块、实体密集和插件命令压力场景。
- [ ] 已验证磁盘空间告警；备份、GC 日志和堆转储不会填满系统盘。
- [ ] Windows 自动更新和计划重启窗口已明确。
- [ ] 生产日志包含隐私/身份信息时，已设置访问权限和保留周期。
- [ ] 结构化健康接口若经反向代理暴露，已启用 TLS、认证、IP 限制和访问日志。
- [ ] 已测试 Paper 崩溃、Velocity 崩溃、端口被占用、健康接口失败和镜像存储不可用。
- [ ] 已测试错误发布自动恢复版本历史；确认不会自动覆盖玩家数据。
- [ ] 已测试人工版本回滚与人工数据恢复是两个独立操作。

## P2：运行治理

- [ ] 每季度执行镜像备份恢复演练。
- [ ] 每次 Paper/Velocity/Geyser/Floodgate 升级都创建新不可变 release，不原地覆盖。
- [ ] 每次升级前检查第三方插件兼容性和配置迁移说明。
- [ ] 每月审阅 watchdog 重启、熔断、自动回滚和备份镜像失败事件。
- [ ] 定期轮换 API key、RCON 和 forwarding secret，并通过配置器重新注入。
- [ ] 维护明确的值班、升级、回滚、数据恢复和安全事件负责人。

## 不可由仓库自动闭环的外部条件

- 真实公网 IP、DNS、DDoS 和云防火墙；
- 硬件容量与峰值玩家压力结果；
- 第三方认证/数据库的服务等级和备份；
- 外部告警供应商和通知链路；
- 法务、隐私、EULA、第三方许可证与内容治理；
- 异地存储是否真的处于不同故障域。

只要其中任一 P0 项仍未确认，状态应标记为“生产候选”，而不是“已完成生产上线”。
